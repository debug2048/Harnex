# Harnex 1.0.0

本次发布提供 Windows、macOS 和 Linux 的桌面安装包、便携 CLI/TUI、VS Code 扩展及完整离线包。

## 下载选择

| 平台 | 架构 | 桌面安装包 | 完整离线包 |
| --- | --- | --- | --- |
| Windows | x64 | `Harnex_1.0.0_win32-x64.exe` | `Harnex_1.0.0_win32-x64_offline.zip` |
| macOS | Apple Silicon | `Harnex_1.0.0_darwin-arm64.dmg` | `Harnex_1.0.0_darwin-arm64_offline.tar.gz` |
| macOS | Intel | `Harnex_1.0.0_darwin-x64.dmg` | `Harnex_1.0.0_darwin-x64_offline.tar.gz` |
| Linux | x64 | 对应的 `.deb`、`.rpm`、`.AppImage` | `Harnex_1.0.0_linux-x64_offline.tar.gz` |
| Linux | ARM64 | 对应的 `.deb`、`.rpm`、`.AppImage` | `Harnex_1.0.0_linux-arm64_offline.tar.gz` |

离线包中的 `portable/runtime/` 内置 Java Runtime、后端、原生 CLI/TUI 与 ripgrep，无需另装 Node.js 或 JDK。`vscode/` 包含 UI 和对应平台 Runtime companion 两份 VSIX；可使用包内的 `install-vscode.ps1` 或 `install-vscode.sh` 安装。

附件另提供各平台原生 CLI 的 npm 包、主 npm 包 `harnex-1.0.0.tgz`、后端 `harnex-1.0.0.jar` 和 Web UI 压缩包。使用独立后端 jar 需要 JDK 17+；模型调用仍需配置可用的模型端点与凭据。

## 本次内容

- 本地与 SSH 远程工作区，共用会话、工具执行和变更审阅能力。
- Web、原生 CLI/TUI、Tauri 桌面和 VS Code 多端入口。
- 对称的 Relay（回路）品牌标识，协调后的 GUI 图标尺寸及带内容版本号的 favicon。
- 完整的跨平台离线分发、源提交校验及 SHA-256 校验清单。
- 统一各入口的工作区身份，修复 Windows 短路径、盘符大小写与特殊字符路径问题。
- 已接入安装后验证脚本；本次实际完成范围与待验证项目见下文，不将脚本存在视为实机验收通过。

## 验证范围

- 五平台附件的源提交、文件大小和 SHA-256 已统一检查。
- macOS ARM64 / Intel、Linux x64 / ARM64 已通过 Runtime 生命周期、数据保留、Unix PTY 和扩展契约检查；Windows 沿用已记录的 Runtime 检查及维护者安装、启动确认。
- macOS/Linux 桌面交互安装和 VS Code Extension Host 端到端验收尚未完成；签名、公证及自动更新也未作为本次交付声明。
- 各项构建记录和附件以 [v1.0.0 发布页](https://github.com/debug2048/Harnex/releases/tag/v1.0.0)为准。首次体验见[下载与首次运行](../04_部署方案.md#0-下载与首次运行)。

## 安装说明

- Windows 要求 Windows 10 1903+/11 x64；安装包未进行发布者代码签名。
- 现有 Windows 包内的 Java 17.0.9 使用 Oracle NFTC 条款；Harnex 自有代码的 Apache-2.0 不替代该组件的许可证。组件声明位置和再分发说明见[第三方组件](../licenses/README.md)。
- 内置 Java 17 的安装目录应避免 emoji 等补充平面字符；Windows 包使用 UTF-8 启动器支持中文及其他跨代码页文字。
- macOS 最低版本为 13；本次通用构建使用 ad-hoc 签名，未进行 Apple Developer ID 签名或公证。
- Linux 桌面依赖 WebKitGTK 4.1 等系统组件；优先使用发行版对应的 DEB/RPM 安装依赖。构建基线为 Ubuntu 22.04。
- 发布页的 `SHA256SUMS` 覆盖全部附件，各平台 manifest 记录版本、源提交及文件哈希。完整离线包内部另有逐文件校验清单。

发布前需完成所声明平台的构建和附件完整性检查；实际可用产物及验证结果以发布页为准。
